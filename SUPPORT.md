# Support

OTelux is an early-stage open source project maintained on a best-effort basis.

## Where to Ask

- Use the bug report form for reproducible defects.
- Use the feature request form for proposed workflows or capabilities.
- Use pull requests for focused, discussed changes.
- Use [private vulnerability reporting](SECURITY.md) for security concerns.
- Use the confidential channel in the [Code of Conduct](CODE_OF_CONDUCT.md) for conduct concerns.

Search existing issues before filing a new one. Include the OTelux version or commit, operating system and architecture, installation method, reproduction steps, and expected behavior.

## Protect Sensitive Data

Telemetry often contains prompts, SQL, URLs, headers, identifiers, source paths, and customer data. Do not attach raw production telemetry, credentials, database files, or unredacted logs to public issues. Prefer synthetic fixtures. If a minimal diagnostic still contains private information, ask for a private channel before sharing it.

## Support Scope

The [Current Baseline](docs/spec.md#current-baseline) defines implemented capabilities and current limits. The project cannot guarantee response times, support every operating system, debug private applications without a reproduction, or maintain unreleased snapshots indefinitely.

The current maintainer is [@b1tank](https://github.com/b1tank). Project decisions and accepted limitations should be recorded in issues, pull requests, specifications, or release notes rather than private conversations.
